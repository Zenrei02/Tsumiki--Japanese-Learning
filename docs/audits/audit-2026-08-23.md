## 6 · Addendum — the deferred task fired twice; this is the second instance's cross-check

The one-off deferred audit launched two sessions. The first wrote §1–§5, the log entry, and
the three tracker fixes. This second instance ran every mechanical check independently before
discovering the collision, then verified the first instance's outputs instead of duplicating
them. **Corroborated independently:** ledger exit 1 with the same 変 diagnosis; drift 0; gap
audit 0 (581 lessons probed); arcs 441/441; deep census green; esbuild clean across all seven
source modules against two negative controls proven to fail first. Three corrections and four
additions follow — each verified against the artifact, not inherited.

**6.1 — §1.1/§3.1 name the wrong file for the 変 fix.** `vocab-data-v1.json` `words[538]` is
*generated output*: `build-vocab-data.py` writes it from `word-ledger-v1.json`, whose 変
reading comes from `KANJI_DICT` — which lives in **`grammar-module.jsx` line 156**:
`["変", "か", "change", "N4"]`, present since the initial commit. The conflict surfaced now
because Session 19's N1 commit (`6e5be0d`) added the correct `["変","へん","strange"]` to the
kanji module's `w:` array. The failing check compares KANJI_DICT against `w:` — neither is
vocab-data — so §3.1's route (edit the JSON, regenerate) would both **revert on regeneration**
and **leave the ledger red**. Correct fix: the one array literal at `grammar-module.jsx:156` →
`["変", "へん", "strange", "N4"]` (or drop the standalone row, per the reviewer), then re-run
`build-word-ledger.py` → `build-vocab-data.py` so it propagates. It is a `.jsx` edit, so it
waits for Lloyd's approval either way.

**6.2 — §2a(b) transposes three scripts, and the one it gets wrong is the headline gate.**
Proven by fixture this morning: **`check-arcs.py` exits 0 on an empty arcs file** — "FAIL:
none — all checks passed" printed over "ALL STAGES: 0/441". Coverage is print-only; the
441/441 line never gates the exit code, so the arc gate's all-clear survives an empty read.
Meanwhile `check-mca.py` and `check-settings.py` **crash** on truly empty items (`min()` of an
empty list) — the same accidental-but-effective guard as `check-scenes.py`, not an exit-0
pass. The silent case for all four is a **partial** module parse: none has a census floor, so
a lesson-shape variant the regex misses shrinks the denominator quietly.

**6.3 — §2a(d)'s "no shared constants remain" missed one, already stale.** The literal
sandbox path `/sessions/adoring-upbeat-mayer/mnt/…` is hardcoded in **`build-verb-data.py:16`
and `build-scenes-render.py:11`** — the same dead constant in two files. Both scripts fail
`FileNotFoundError` in every new sandbox session. Fix is the `pathlib.Path(__file__).parent`
idiom their siblings use.

**6.4 — additional sweep members, same shapes.** `check-module-drift.py`: when extraction
finds a shared function in fewer than two modules it reports "nothing to compare" and exits 0
— an extraction failure degrades to a pass; and its storage-keys section, which its own
docstring calls "the real seams," can never fail — a renamed key prints as two one-module
rows with no ❌. `curriculum-gap-audit.py` `probe_hits()`: a multi-regex probe falls back
from all-match to any-match when all-match finds nothing — "covered (partial match)" weakens
the probe exactly when it is about to fail, with no exit-code effect. `build-vocab-data.py`:
a missed `@@WORDS` marker prints a WARNING and **exits 0**, and there is no post-splice
census of the block (the Session 19 corollary, unapplied here).

**6.5 — §3.2's open check is now closed:** the stopgap is **still live** —
`vocab-notes-v1.json`'s 勉強する and 散歩する cards still teach the noun+する pattern.
Redundant with `sb-suruverbs`, not wrong; shrink-to-pointer stays queued.
