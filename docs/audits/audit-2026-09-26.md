### esbuild compile sweep — 42/42, and a harness that had to be thrown away first

**The first harness passed all three negative controls and failed its positive one**, which is
the only reason its 20/31 "result" was not reported as eleven broken modules:

```
ctl synthetic broken        -> exit 1   (want 1)  ✅
ctl real storage.js broken  -> exit 1   (want 1)  ✅
ctl real Grammar.jsx broken -> exit 1   (want 1)  ✅
ctl unmodified storage.js   -> exit 1   (want 0)  ❌  <- harness, not the file
```

Cause: `--bundle`, which resolves `react` and friends against a `node_modules` the scratch dir
does not have, so every module with an import "failed to compile" for a reason that has nothing
to do with compiling. **Three negative controls all passing is not evidence of a working
harness** — a harness that always exits 1 passes every one of them. This project's standing
rule is "prove the harness can fail"; the missing half is *prove it can pass*.

Re-run without `--bundle`, parse-and-transform only, all five controls proven in both
directions:

```
ctl unmodified storage.js   -> exit 0   (want 0)  ✅
ctl unmodified Grammar.jsx  -> exit 0   (want 0)  ✅
ctl synthetic broken        -> exit 1   (want 1)  ✅
ctl real storage.js broken  -> exit 1   (want 1)  ✅
ctl real Grammar.jsx broken -> exit 1   (want 1)  ✅
PASS=42 FAIL=0
```

esbuild 0.28.2 in `$HOME/eb`; scratch in `$HOME/ebwork`, never the project folder. Covered: the
twelve root `.jsx`, `tsumiki-app/src/*.jsx`, `src/modules/*.jsx`, `src/lib/*.js|jsx` and
`src/data/*.js`, all under `--loader:.js=jsx` so a `.js` holding JSX is not a false pass.

### ① `docs/design/dictionary-drawer-design-v1.md:409` — two faults in one line

Current text, under "What it must not do":

> `- Must not show romaji. `check-romaji-leak.py` should cover the new surface.`

**Fault 1, the one Session 35 flagged and left open.** The line reads as a flat prohibition,
and the dictionary now takes romaji *input*. It does not violate the rule — `dictionary-module.jsx`
contains no `toRomaji`, no romanisation function of any kind, and echoes the conversion back
**as kana** ("Reading that as たべる") — but a reader arriving at line 409 cold has no way to
know that, and the obvious response is to revert the feature.

**Fault 2, not previously recorded, and the more serious of the two.** The sentence names a
safeguard that cannot exist. `check-romaji-leak.py` reads the **eval workbook**
(`DEFAULT = 'naoshi-eval-v1-with-outputs.xlsx'`, line 56; `load_workbook(path)['Blind Grading']`,
line 141). It has no path by which it could ever see the drawer. So the doc records a check
covering a surface the check cannot reach — a check that cannot fail, which is the exact family
this project has been bitten by four times.

Suggested replacement:

> `- Must not show romaji. INPUT IS EXEMPT: wāpuro romaji in the search box is how a learner`
> `  who cannot yet read kana reaches the dictionary at all; romaji goes in, kana and kanji`
> `  come back, and the conversion is echoed as kana. The banned thing is transliteration of`
> `  output, not translation of input (see input-romaji-layer-spec-v1.md).`
> `  ⚠️ check-romaji-leak.py does NOT cover this surface and cannot — it reads the eval`
> `  workbook's Blind Grading sheet, not any module. There is no automated check here.`
