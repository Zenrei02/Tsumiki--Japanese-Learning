### ① `test-autosave.fixtures.mjs:93` — make the fake `upsert` chainable (the §1① fix)

**Current:**

```js
        upsert: async (obj) => {
          calls.push({ op: "POST", data: { ...obj.data } });
          const same = JSON.stringify(obj.data) === JSON.stringify(row.data);
          row = { data: { ...obj.data }, version: same ? row.version : row.version + 1 };
          return { error: null };
        },
```

**Suggested** — returns a builder instead of a Promise, so `.select("version").maybeSingle()`
resolves, and hands back the version the way the real database does:

```js
        upsert: (obj) => {
          calls.push({ op: "POST", data: { ...obj.data } });
          // The archive trigger's own rule: an identical document is not a new
          // version. Modelled here so a test can assert the version DID NOT move.
          const same = JSON.stringify(obj.data) === JSON.stringify(row.data);
          row = { data: { ...obj.data }, version: same ? row.version : row.version + 1 };
          // ⚠️ NOT a Promise. sync.js chains .select("version").maybeSingle() onto
          // this (added 5978017), and only the SERVER may supply the version —
          // noteAccountVersion ignores a missing or lower one, so returning
          // nothing here would make the stale-read check silently a no-op.
          const built = { version: row.version };
          return {
            select: () => ({ maybeSingle: async () => ({ data: built, error: null }) }),
          };
        },
```

**Two things to prove after applying it**, because a green result that arrives easily is the
thing this project distrusts:

1. `python3 test-autosave.py` → exit 0 with no `autosave failed, will retry` lines at all.
   Those lines disappearing is the real signal; the assertions passing is downstream of it.
2. `python3 test-autosave.py --self-check` → **part 1 green, part 2 red.** Part 1 green is what
   proves the environment faithful; without it the red means nothing. This is the control that
   has not been able to run since Sep 29.

A third check is worth one line: assert the version the fixture returns actually lands, e.g.
that `version()` does not move on a re-send of an identical document. The fixture already models
that rule and nothing currently reads it.

**⚠️ This fix is not a suggestion on paper — it was applied to a full copy of the folder outside
the mount and run. The project folder was not touched** (`test-autosave.fixtures.mjs` md5 in the
project is unchanged at `f68c92da…`; the patched copy is `b6f4890…`, and git reports the file
clean). Both proofs above hold:

```
patched, plain run          -> EXIT=0   "ALL AUTOSAVE TESTS PASS"
                                        autosave-retry lines: 0   ← the real signal
patched, --self-check
  CONTROL PART 1 unmutated  -> GREEN    "ALL AUTOSAVE TESTS PASS"
```
